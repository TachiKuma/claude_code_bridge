# ADR 0001：三层运行时权威边界（WezTerm / Herdr / CCB）

- 状态：已接受
- 日期：2026-08-23
- 关联方案：`plans/architecture-optimization/herdr-runtime-hosting-optimization-plan.v2.zh-CN.md`
- 关联基线：`plans/architecture-optimization/herdr-runtime-hosting-optimization-plan.zh-CN.md`
- 关联术语：仓库根 `CONTEXT.md`
- 关联规划（deferred）：`docs/plantree/plans/windows-wezterm-native/`

## 背景

在 Native Windows 上，终端栈由三层组成：WezTerm（GUI 前台）、Herdr（agent 运行时）、CCB
（协作控制面）。历史上 CCB 同时扮演运行时宿主、provider 控制面与状态投影层，导致职责边界
过宽、状态权威重叠（archi 治理分数偏低），并出现两类症状：

1. **前台静默降级**：CCB 直接 `wezterm cli spawn` 进活动窗口，缺 mux 时错误被丢弃，无法区分
   「已 attach」与「spawn 失败」。
2. **运行时状态被误当业务权威**：Herdr 的 `done` / `idle` / `unknown` 若被直接映射为 job 成败，
   会伪造业务完成或把不确定状态降级为空闲。

两类症状同源：**把运行时/前台的「事实」当成了业务「判定」。**

## 决策

确立三层职责权威边界，作为难以逆转的架构约束：

1. **WezTerm = 前台事实源（Frontend Surface）**：提供前台可见性事实（mux 是否可用、attach 落点），
   不承担运行时或业务权威。前台不可用必须显式暴露，不得静默降级为「已 attach」。
2. **Herdr = 运行时事实源（Host Runtime）**：作为 physical pane owner 提供 pane 生命周期与 agent
   运行时状态（`idle/working/blocked/done/unknown`）。它**不是业务完成权威**；`done` 仅表示运行时
   完成，`unknown` 不等于 `idle`。
3. **CCB = 业务完成权威（Collaboration Control Plane）**：唯一判定 job/ask 成败、可恢复性、
   continuation、取消语义，持有 provider 命令/凭据/原生 session。CCB **消费并校验**前两层的事实，
   但不以其替代业务判定。

推论约束：

- 所有运行时/前台的「事实」都不足以关闭 job 或声明业务成功。
- `unknown`、断线、过期 generation、事件缺口、缺 mux 均须**显式**暴露，不得静默降级。
- 运行时锚点（Runtime Binding）绑定 project / workspace / pane / agent slot / provider kind /
  session / runtime generation；前台事实以可选 `frontend` 段记录，`window_id` 仅诊断、不作重连锚点。

## 后果

**正面**：

- 状态权威不再重叠，治理复杂度下降，符合 v2 的边界收敛主干。
- 前台缺 mux 从「静默失败」变为「可观测回退」，attach 首屏可靠性可测。
- 运行时状态与业务状态在 Agents 面板中并存而不混为一个权威。

**代价 / 约束**：

- CCB 必须始终校验并可能拒绝下层事实（多一层校验成本）。
- 契约模型需承载前台维度（binding 增 `frontend` 段），事件消费需按 generation/seq 去重。
- 该边界一旦确立，后续任何「让下层直接决定业务完成」的捷径都被禁止。

## 备选方案

1. **让 Herdr 承担业务完成权威**（`done` 直接关 job）：被否。会伪造业务完成，且把 provider 语义
   泄漏进运行时层，与凭据/恢复权威冲突。
2. **让 WezTerm 成为 mux 后端并统管前台+运行时**（`WezTermBackend`）：本轮否，标记 deferred。
   可行性与搁置理由已由 `docs/plantree/plans/windows-wezterm-native/` 记录；如未来激活需独立 ADR
   与原型验证。
3. **维持 CCB 同时当宿主+控制面+投影层**（现状）：被否。正是治理分数偏低与前述两类症状的根因。

## 修订（2026-08-24，Herdr 源码验证）

本次以实机（Herdr 0.8.2）+ Herdr 源码（`E:\GitHub开源项目\herdr-master`，271 个 Rust 文件）验证
本 ADR。三层划分**成立且被印证**，但需**修正第 2 层「Host Runtime」的权威方向假设**——v2 方案曾
设想把 agent 身份与 pane 重启/backoff **下放给 Herdr**（`runtime.ensure`/`agent_id_authority`/
restart-backoff），源码证明该方向**误设**：

1. **Herdr 是观测式状态聚合器，不是身份/重启权威。** `Agent` 是 22 种类的 `Copy` enum
   （`src/detect/mod.rs:43`），无 `AgentId`/实例 id 类型；检测靠查进程 + 屏幕匹配
   （`process_agent_hint`、`live_prompt_box`），Herdr **不接收也不铸造** agent 身份令牌。
2. **agent 身份进程绑定且瞬态。** `clear_agent_runtime_identity_after_respawn()`
   （`src/app/agent_resume.rs:260`）在 respawn 时主动清身份——「reconnect 后 agent_id 不漂移」
   在设计上不可能。
3. **Herdr 从外部接收权威。** `handle_pane_report_agent`（`src/app/api/panes.rs:1231`）以
   `source`+`seq` 仲裁多源状态；CCB 的 `report_pane_agent` 与 agent **自带的 hook**
   （`src/integration/assets/claude/herdr-agent-state.sh`）是**对等权威来源**。
4. **Herdr 无 agent restart/backoff。** `respawn_shell_on_exit`（`src/terminal/state.rs:146`）
   仅在 agent 退出后重开 shell 保住 pane，非带 backoff 的 agent 重启；cleanup 仅手动
   `workspace.close`/`pane.close`。

**修订结论**：**Agent 身份与 pane 重启/backoff 策略恒属 CCB，不下放 Herdr。** Herdr 的职责精确
表述为「前台承载 + 观测式运行时状态聚合」，它**接收** CCB 的 agent 身份报告，而非成为身份权威。
备选方案 1（让 Herdr 承担业务/身份权威）据此进一步坐实为**架构上不可行**，非仅「本轮不做」。

据此，`.scratch/wezterm-ccb-herdr-hosting/issues/` 中 **13A（Herdr agent_id 权威）、13B（删除 CCB
补身份路径）、12C（restart/backoff/cleanup 下放）判为 `wontfix`（已被本修订取代）**，不再挂
`blocked-upstream`。证据见
`plans/architecture-optimization/topics/herdr-0.8.2-native-capability-probe.md`。
