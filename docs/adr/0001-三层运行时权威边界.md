# ADR 0001：三层运行时权威边界（WezTerm / Herdr / CCB）

## 背景

在 Native Windows 上，终端栈由三层组成：WezTerm（GUI 前台）、Herdr（agent 运行时）、CCB
（协作控制面）。历史上 CCB 同时扮演运行时宿主、provider 控制面与状态投影层，导致职责边界
过宽、状态权威重叠（archi 治理分数偏低），并出现两类症状：

1. **前台静默降级**：CCB 直接 `wezterm cli spawn` 进活动窗口，缺 mux 时错误被丢弃，无法区分
   「已 attach」与「spawn 失败」。
2. **运行时状态被误当业务权威**：Herdr 的 `done` / `idle` / `unknown` 若被直接映射为 job 成败，
   会伪造业务完成或把不确定状态降级为空闲。

两类症状同源：**把运行时/前台的「事实」当成了业务「判定」。**

## 决策

确立三层职责权威边界，作为难以逆转的架构约束：

1. **WezTerm = 前台事实源（Frontend Surface）**：提供前台可见性事实（mux 是否可用、attach 落点），
   不承担运行时或业务权威。前台不可用必须显式暴露，不得静默降级为「已 attach」。
2. **Herdr = 运行时事实源（Host Runtime）**：作为 physical pane owner 提供 pane 生命周期与 agent
   运行时状态（`idle/working/blocked/done/unknown`）。它**不是业务完成权威**；`done` 仅表示运行时
   完成，`unknown` 不等于 `idle`。
3. **CCB = 业务完成权威（Collaboration Control Plane）**：唯一判定 job/ask 成败、可恢复性、
   continuation、取消语义，持有 provider 命令/凭据/原生 session。CCB **消费并校验**前两层的事实，
   但不以其替代业务判定。

推论约束：

- 所有运行时/前台的「事实」都不足以关闭 job 或声明业务成功。
- `unknown`、断线、过期 generation、事件缺口、缺 mux 均须**显式**暴露，不得静默降级。
- 运行时锚点（Runtime Binding）绑定 project / workspace / pane / agent slot / provider kind /
  session / runtime generation；前台事实以可选 `frontend` 段记录，`window_id` 仅诊断、不作重连锚点。

## 后果

**正面**：

- 状态权威不再重叠，治理复杂度下降，符合 v2 的边界收敛主干。
- 前台缺 mux 从「静默失败」变为「可观测回退」，attach 首屏可靠性可测。
- 运行时状态与业务状态在 Agents 面板中并存而不混为一个权威。

**代价 / 约束**：

- CCB 必须始终校验并可能拒绝下层事实（多一层校验成本）。
- 契约模型需承载前台维度（binding 增 `frontend` 段），事件消费需按 generation/seq 去重。
- 该边界一旦确立，后续任何「让下层直接决定业务完成」的捷径都被禁止。

## 备选方案

1. **让 Herdr 承担业务完成权威**（`done` 直接关 job）：被否。会伪造业务完成，且把 provider 语义
   泄漏进运行时层，与凭据/恢复权威冲突。
2. **让 WezTerm 成为 mux 后端并统管前台+运行时**（`WezTermBackend`）：本轮否，标记 deferred。
   可行性与搁置理由已由 `docs/plantree/plans/windows-wezterm-native/` 记录；如未来激活需独立 ADR
   与原型验证。
3. **维持 CCB 同时当宿主+控制面+投影层**（现状）：被否。正是治理分数偏低与前述两类症状的根因。
