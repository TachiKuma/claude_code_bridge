# ADR 0002：观测聚合协作模型（WezTerm / Herdr / CCB 的配合方式）

- 状态：已接受
- 日期：2026-08-25
- 关联决策：`docs/adr/0001-三层运行时权威边界.md`（本 ADR 是其在"配合方式"层的落地）
- 关联证据：`plans/architecture-optimization/topics/herdr-0.8.2-native-capability-probe.md`
- 关联术语：仓库根 `CONTEXT.md`（`observational state aggregator`、`agent identity authority`）
- 关联上游诉求：`plans/architecture-optimization/open-questions.md`

> 2026-08-26 修订：本 ADR 原文中“CCB 独立状态权威、过滤 Herdr 原生 hook、用 CCB monotonic seq
> 抢占状态”的实现约束已被 ADR 0003 的 2026-08-26 修订取代。保留的边界是 CCB 的
> project/slot/provider/generation 身份权威与业务完成权威；Herdr UI Agents 面板的工作状态应回到
> Herdr 自身观测链。

## 背景

ADR 0001 确立了三层**权威边界**（WezTerm=前台事实、Herdr=运行时事实、CCB=业务完成权威）。
但 v2 方案曾在此之上假设一条「把运行时/身份权威**下放给 Herdr**」的轨迹（`runtime.ensure`、
`agent_id_authority`、restart/backoff），并把 `ensure_runtime` 描述为「等 Herdr 原生能力成熟即
切换」的临时兼容层。

2026-08-24/25 以实机（Herdr 0.8.2）+ Herdr 源码（`E:\GitHub开源项目\herdr-master`，271 Rust 文件）
验证后，该下放方向被证伪（见 ADR 0001 修订节与探针文档）：Herdr 架构上是**观测式状态聚合器**，
不铸造 agent 身份、无 agent 重启策略，并从 CCB 与 agent 自带 hook 等**对等来源接收**状态。本 ADR
据此把三者的**配合方式**（而非边界）重新钉死，并清理误设残留。

## 决策

采用**观测聚合协作模型**，一句话锚点：**CCB 权威 · Herdr 观测 · WezTerm 呈现**。

### 1. CCB↔Herdr 状态通道：原生 events 为主，polling 兜底

Herdr 原生提供 `events.subscribe`/`events.wait` + 细粒度 `pane.agent_status_changed` 等事件。目标
架构以**原生 events 订阅为主状态通道**，snapshot polling 降为兜底。这修正了 10B 关闭时"真正上游
事件源仍待 Herdr 提供"的错误前提——事件源一直存在。

### 2. agent 身份/种类权威：CCB 拥有的 pane，CCB 上报压过屏幕检测

Herdr 靠**查进程 + 屏幕模式匹配**观测 pane 里是哪种 agent（会误检测）。对 **CCB 亲手启动的
pane**，CCB `report_pane_agent`（`--source ccb`）的 agent 种类/身份为**权威**，Herdr 屏幕检测仅
兜底（用于非 CCB 启动的 pane）。契约化 `source` 优先级：CCB 拥有的 pane，`source=ccb` 优先级最高。

### 3. WezTerm↔Herdr：呈现 vs mux，非竞争

WezTerm 是 **OS 窗口宿主（presentation）**：提供可见窗口与 attach 落点
（`wezterm cli spawn -- herdr session attach <session>`）。Herdr 是**窗口内的真实 mux / pane
存活所有者**。二者**不是竞争的 mux**。deferred 的 (B)「单一权威 mux + workspace 寻址」维持搁置
（需 `/prototype`，见原 spec Out of Scope）。

### 4. `ensure_runtime` 是永久 CCB 职责，不是过渡兼容层

Herdr 不会有 `runtime.ensure`（源码证明它不是那种系统）。故 CCB 的 `ensure_runtime(manifest)`
是**永久的运行时收敛职责**，文档与契约中去除「兼容层/过渡/待上游」措辞。

### 5. agent 自带 hook 与 CCB 上报的关系（经源码验证固化）

`herdr integration install` 会把 hook 写进 agent 自身配置，让 agent 从内部经 socket 自报（claude
的 `herdr-agent-state.sh` 报 `pane.report_agent_session`：session_id/transcript，`source=herdr:claude`，
`seq=time.time_ns()`）。**CCB 不安装、也不采纳原生 hook**，保持 `source=ccb` + 单调 `seq` +
启动时 `release_pane_agent` 抢占的**独立状态权威**。理由与风险：

- **不装 hook**：装了会形成竞争来源，且 hook 的 `seq=time.time_ns()`（~1.7e18）会永远压过 CCB 的
  小整数 seq，架空 CCB 状态权威；hook 还要改写 CCB 作为 provider 权威在管的 agent 配置，二者冲突。
- **可利用其产物**：原生 hook + 屏幕检测让 Herdr 拥有比 CCB `BUSY/IDLE` 二值**更细的
  `agent_status`**（working/blocked/idle/done）。CCB 采纳通道①后，可**消费该 `agent_status` 作为
  运行时事实**丰富读模型——严格作为运行时状态、不改业务完成权威（守 ADR 0001）。

## 后果

**正面**：

- 三者配合从"等一个永不到来的 Herdr 能力"转为"利用 Herdr 既有的事件与检测"，方向纠正。
- 状态通道低延迟（events 替代轮询）；agent 种类不再被屏幕启发式误覆盖；运行时状态粒度可提升。
- `ensure_runtime` 叙述不再误导后来者；三者职责在 CONTEXT 有稳定术语。

**代价 / 约束**：

- CCB 必须持续作为独立状态权威主动上报，且**保证其管理的 pane 不被安装原生 hook**（否则 seq
  架空）。
- 消费 Herdr `agent_status` 时须严守"运行时事实 ≠ 业务判定"，不得据其关闭 job。

## 备选方案

1. **CCB 采纳/安装 Herdr 原生 hook 作为状态源**：被否。seq 量级碾压会架空 CCB 权威，且侵入
   provider 配置。
2. **维持 snapshot polling 为主通道**：被否。放弃了 Herdr 既有的原生 events，延迟与开销更高。
3. **让 Herdr 承担 agent 身份/重启权威（原 v2 下放设想）**：被否，且经源码验证为**架构上不可行**，
   非仅"本轮不做"（见 ADR 0001 修订节；12C/13A/13B 已判 wontfix）。

## 候选实现 backlog（本轮只记名，不开工；符合"先 ADR 后按需 spec"）

按优先级 1 > 2 > 4 > 3 > 5：

1. **采纳 Herdr 原生 `events.subscribe` 为主状态通道**，polling 兜底（修正 10B 前提）。
2. **契约化 `source=ccb` 对 CCB 拥有 pane 的身份/种类权威**，压过屏幕检测。
3. **CCB 消费 Herdr 更细 `agent_status` 丰富运行时读模型**（依赖 1；严守运行时事实语义）。
4. **`ensure_runtime` 去"兼容层/过渡"叙述**，重构为永久 CCB 职责（纯文档/契约）。
5. **防 seq 架空**：确保 CCB 管理的 pane 不被安装原生 hook，或消解 CCB seq 与 hook `time_ns` seq
   的量级冲突（风险项）。

## Herdr 上游诉求（记名，不实现；详见 `open-questions.md`）

- **(i) 统一/文档化多源仲裁的 seq 语义与 source 优先级**：让 `source=ccb` 能**显式声明高优先级**，
  而非靠 seq 量级碰运气。
- **(ii) 可选暴露稳定 pane-agent 关联**便于 CCB 对账——**但不作为 agent_id 权威**，仅只读关联。

## 修订（2026-08-26，状态权威收窄）

ADR 0003 的前台 attach 与 Herdr 观测约束进一步修正本 ADR 第 2、5 节：

1. **CCB 不再作为 Herdr 工作状态权威。** 对 CCB 管理的 pane，CCB 仍负责
   project/slot/provider/generation 与业务完成判定，但不再用 `report_pane_agent` 持续写入
   `working`、`idle` 等 runtime 工作状态。
2. **Herdr 原生 hook 应被保留。** CCB 管理的 provider home 不再因 seq 竞争假设删除
   `herdr-agent-state`、`pane.report_agent_session` 或等价 Herdr 原生状态 hook；这些 hook 属于 Herdr
   自身观测链。
3. **seq 不再用于 CCB 状态抢占。** CCB 不再维护用于 Herdr `source=ccb` 状态上报的 monotonic seq；
   Herdr 的 source/seq 仲裁只用于 Herdr 原生观测来源之间的运行时事实处理。
4. **身份与状态分离。** CCB 身份事实优先通过 `set_pane_identity` / metadata token 表达；若未来需要
   identity-only agent 注册，应另行设计 API，不能复用会写入工作状态的 `report_pane_agent`。
