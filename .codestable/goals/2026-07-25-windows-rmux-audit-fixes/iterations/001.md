# Iteration 001

## Current Understanding

本 goal 绑定 Windows Rmux Native Backend 审计报告中的 4 条 finding。目标不是扩展架构或处理 arch-drift，而是对每条 finding 做生产路径修复并补回归测试。

方案深度判断：

- finding-01 是正确性关键路径，不能只在测试 fake 中规避，必须在 additive patch 的 sidebar/tool pane 物化路径传播 replacement pane id。
- finding-02 是客户端健壮性/安全边界，必须在真实读取循环中加上限。
- finding-03 是全局 cache 状态错误，保留现有缓存设计并补齐 backend impl 状态，比删除缓存更小且符合现有 `TerminalBackendSelection` 语义。
- finding-04 是长期维护的命令转译边界，使用小型 quote-aware 分段 helper，不引入完整 shell parser。

## Implementation Approach

按审计 finding 分别做局部修复：

- 捕获 `respawn_pane` 返回值，并将 `%...` replacement pane id 写回 result、identity 和 `created_panes`。
- 给 ccbd 客户端响应读取增加 `_MAX_RESPONSE_BYTES = 1024 * 1024`。
- 让 `api_selection.resolve_backend` 返回 backend 与缓存实现名，API 层保存 `_backend_cache_impl`。
- 用 `_split_shell_segments` 替换裸 `split(';')`，只在 quote 外分号切分。
